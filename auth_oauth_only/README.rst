Lets a database require an OAuth provider (for example Google) for every
internal user, while a small group keeps the password as a break-glass.

When the option is enabled:

- a password that matches for an internal user outside the group *May
  sign in with a password* is refused, on the web login form and over
  XML-RPC/JSON-RPC alike, and a warning naming the login and the channel
  is logged;
- API keys, OAuth tokens, passkeys, SAML and portal users keep working,
  and so does a password re-check of the user already signed in to the
  session (the identity check before creating an API key or changing the
  password);
- the login page shows only the OAuth provider buttons;
  ``/web/login?password=1`` shows the normal form;
- the public *Reset Password* form refuses internal users who must use
  OAuth. The administrator's invitation and reset buttons are not
  affected.

The refusal is the usual "Wrong login/password": a specific message
would confirm that the password was right.

Configuration
=============

1. Make sure the OAuth provider works for your users.
2. Move integrations that log in over RPC with a password to an API key.
3. Add yourself, and whoever else needs a break-glass, to the group *May
   sign in with a password* (category *Extra Rights*). Nobody gets it on
   install.
4. In *Settings > General Settings > Integrations*, tick *Sign in only
   with OAuth*. Odoo refuses to save it while the group has no active
   internal member.

The option is the system parameter ``auth_oauth_only.enabled``; setting
it to ``False`` (or unticking the option) turns the module off at once.

Usage
=====

Internal users click the provider button on the login page. Members of
the break-glass group open ``/web/login?password=1`` to get the password
form.

Known issues / Roadmap
======================

- The rule lives in ``res.users._check_credentials`` and treats the
  ``auth_method`` values ``password`` and ``ldap`` as a password. It
  sees the final result of every override loaded before it
  (``auth_ldap``, ``auth_passkey``, ``auth_saml``,
  ``auth_oauth_multi_token``, ``auth_admin_passkey``); a module that
  depends on this one and catches ``AccessDenied`` to re-authenticate
  the same password would bypass it.
- Emptying the break-glass group while the option is on is not
  prevented.
- Portal users keep their password, but the login page hides the form
  for them too: they need ``/web/login?password=1``.
